# 签名旅行请求与预算协商（模拟R1）

入口：金融任务→旅行请求→获取签名机票与住宿报价。收件箱验证travel-agent-demo身份、HMAC、session:goal主体、五分钟时间窗口与唯一nonce；报价明确CNY、基价/税/费总额、商户/类别、退改和十五分钟有效期。拒绝伪造、重放、错主体、过期、不支持币种和金额不一致请求。

接受请求仅允许进入订单核对，不产生付款权限或资金预留。拒绝后不能使用该批报价付款。创建/编辑Mandate和最终订单付款仍走独立准确确认；旧确认在请求被新报价替代后失效。

预算协商：输入住宿总预算向固定模拟商户重新询价。合成报价单轮按当前基价最多下降5%，税费不变，优惠报价改为不可退款；无法满足预算返回失败且不改变原报价。成功后产生签名新请求、revision与replaces关系，原请求标记已替代。用户必须重新接受新退改，再独立确认最终订单。已提交/未知/已付的原订单不能被改价覆盖。

仅提供两个固定模拟商户、CNY报价和确定性的预算规则，不宣称开放市场最优价格或实时商户网络协商。新请求签名密钥只来自服务端环境变量；未配置则为进程随机密钥，重启后旧签名需重新获取。真实提供商网络、持久Outbox和长期任务迁移仍属于剩余X-A08范围。

测试：travel-inbox.test.ts、travel-inbox-http.test.ts、travel-inbox.spec.ts及financial-services.spec.ts；最终结果见开发检查点。
