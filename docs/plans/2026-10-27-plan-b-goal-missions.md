## B1 核心体验

用户说：“我想去日本旅行，希望不动应急金，帮我把资金安排好，必要的操作让我确认。”

系统显示目标差额、可用资金、待到账资金、风险和下一步。Agent 可以建议取消不需要的订阅、比较投资流动性、安排旅行金和检查支付卡；每项动作有独立的拒绝和恢复路径。

不是强制用户做完六种操作才允许完成目标。六类能力通过一条旅行主任务、一个长期目标分支和单独业务入口完整覆盖。

## B2 六场景与目标闭环

| 场景 | 用户任务 | 目标联系与验收 |
| --- | --- | --- |
| 账单 | 导入数据，查看月度/年度消费和异常，修正分类 | 每个节省建议链接证据；纠错会改变预算和方案；历史流水不覆盖余额 |
| 订阅 | 判断并取消不用的云盘、暂停后续计划、设置年费提醒 | 验证取消后才改变未来现金流；不把 ¥68 直接加到当前旅行金；误判可否认 |
| 智能转账 | 联系人转账、工资到账转旅行金、同行 AA | 联系人需唯一匹配；工资未到账跳过；同行应收仅到账后进入目标余额；预览显示其他目标影响 |
| 理财 | 比较产品和风险；为期限匹配的长期目标申购；旅行临近时赎回已有合适持仓 | 活期、份额、预留、待结算严格区分；禁止用预期收益弥补确定性预算缺口；赎回未到账不得订票 |
| 卡片 | 申请旅行卡、模拟额度评估、限制境外/线上交易、解锁和挂失 | 限制影响支付路由；提高信用额度不增加目标存款；挂失要求新支付方式，不能普通解锁 |
| 跨场景 | 旅行 Agent 给出机票/住宿报价，NOVA 核对预算、可用卡和授权，用户确认后下单并跟踪 | 任务状态由实际工具结果推进；报价涨价/费用变化重确认；部分成功不重复支付已成功订单 |

短期旅行任务优先保障流动性。理财申购放在合适期限的长期目标分支，不为了展示理财而强行给临近出发的用户买产品。若赎回 T+1，机票报价先失效，到账后必须重新报价与确认，不能沿用旧价成交。

## B3 三条可演示故事

### B3.1 旅行准备成功

目标与保护金 → 账单证据 → 取消订阅 → 比较三个计划 → 激活工资事件储蓄 → 同行 AA 到账 → 检查旅行卡限制 → 接收新报价 → 预留已到账资金 → 单独确认机票/住宿 → 订单与目标进度。

AA 未收款、未来工资、预测收益都不能用于支付预算。报价超限则给出换报价、调整目标或不执行选项。

### B3.2 出发前资金与支付变化

查看已有理财持仓 → 评估赎回到账日及费用 → 确认赎回 → 等待结算 → 新报价 → 卡被锁定或挂失 → 用户确认解锁可解锁的卡/选择其他支付方式 → 再核对资金 → 付款。

如果住宿已成功、机票失败，任务展示已完成和待处理部分，保留资金占用事实，查询/替换失败项；不把整个任务标为成功或把已扣资金还原。

### B3.3 长期目标建立

用户另建培训金/应急补足目标 → 多目标优先级 → 风险和期限问卷 → 三产品比较 → 解释“保留现金”选项 → 选择匹配产品 → 单独确认申购 → 份额/估值/目标进度 → 调整与赎回。

培训金与旅行金共享同一资金上限，不能分别算出两份“足够的钱”。适当性不匹配时支持留在现金，不逼迫投资。

## B5 模拟数据设计

保留旧旅行基准，新增三套隔离 Fixture：

1. `mission-travel-complete`：三账户、两个目标、十二订阅、联系人/AA、卡片、机票/住宿报价。账单扩展至完整历史年度和当前 YTD，所有来源可追溯。
2. `mission-liquidity-repair`：持仓赎回 T+1、报价 15 分钟过期、卡锁定/挂失、商户部分成功、退款处理中；故障由模拟 Provider 事件产生。
3. `mission-long-term`：三种风险偏好、六产品、不同期限和费用、三个目标争用、月末资金低谷；包含“不适合买任何产品”的可解释结果。

再以参数生成至少十二组变体：工资早/晚/未到、联系人同名、AA 部分到账、订阅误判、产品停购、赎回失败、卡申请待审、限额拒绝、报价涨价、余额冲突、订单未知、部分退款。每组能重置、回放和复算，不靠测试前手工补状态。

## B7 主要风险与验收

风险一是故事太长：主演示约九分钟，复杂分支另作可独立进入的现场追问，不要求一次录屏塞完所有异常。风险二是“目标进度”虚增：页面分别列已存、待收、待结算、预测，不把它们加成可支付金额。

六类独立入口按共同矩阵验收；三故事额外验证任务取消、局部成功、授权失效、到期报价、目标抢占与人工交接。实际模型只允许选择/调用受控工具；重复提交、刷新、进程重启不产生重复订单。

反馈可直接指定 B3.x/B4.x：旅行是否继续为主故事、是否采用长期目标分支、理财和卡片要重点展示哪些操作、跨场景优先机票住宿还是生日预订。
