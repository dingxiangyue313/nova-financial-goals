# 方案 C：对话驱动的银行任务工作台

讨论稿 v1。11 月 2 日交付。定位：保留目标首页和现有 NOVA 导航，把六类业务建设为同一个可检查、可暂停、可恢复的 Agent 任务体系。重点证明自然语言到业务结果的受控执行。

## C1 核心体验

用户输入一个或多个需求，NOVA 显示“理解了什么、缺什么、准备查什么、哪些步骤要确认”。工具返回实际证据后再决定下一步；用户可改计划、拒绝某一步或停止任务。

复用现有 AgentTask、AgentRun、工具预算、会话和组件，不重写一个新的通用 Agent 平台。11 月 2 日版本限制在四类任务模板，模型可以在模板中选择工具和恢复路径，不能生成任意可执行代码。

模板：日常转账与 AA、账单及订阅优化、理财与卡片办理、跨场景生活服务。所有六类仍有直接入口和可编辑表单，模型不可用时可继续操作。

## C2 六类任务及实际输出

| 场景 | 对话示例 | 工作台必须生成的结果 |
| --- | --- | --- |
| 转账 | “给小林转 300，明月起每月 500，晚餐 398.01 四人 AA” | 联系人消歧、独立的一次性/周期确认、整数分拆分单与应收状态；不能一条确认覆盖无关动作 |
| 分析 | “总结去年消费，调查这几笔异常” | 时间覆盖、分类/基线、异常线索、逐笔证据、用户更正与重算；不能把异常线索写成欺诈结论 |
| 订阅 | “找出续费项目，这个保留，另一个取消” | 候选确认、多个独立处理项、提醒、取消结果/未知查询；准确保存用户否认和保留偏好 |
| 理财 | “钱三个月后要用，比较产品，合适再买；赎回原持仓” | 风险/期限补问、可比较产品、流动性约束、单独申购/赎回预览、份额/结算结果；不匹配可以不买 |
| 卡片 | “申请卡，调额度，限制线上交易；这张丢了” | 申请/审核状态、额度决定、限制/解锁、挂失确认与新状态；信用额度与现金分离 |
| 联动 | “给妈妈订生日鲜花和蛋糕，总共不超过 600” | 可编辑预算/商户授权、报价、预留、两个订单、交付跟踪、部分失败与人工出口 |

“明月”等歧义时间必须澄清或明确归一化后展示用户核对；未确认的口语解析不能直接产生定时扣款。

## C3 Agent 任务模型

拟扩展而非替换既有模型：

- `TaskPlan`：用户目标、约束、步骤、依赖、所需授权、整体截止时间、当前版本。
- `TaskStep`：领域、输入工件引用、输出工件引用、状态、是否需要用户确认、恢复选项。
- `DomainToolResult`：类型化结果、来源、金额/日期、精度、失败代码；原始账单文字始终作为数据。
- `ActionProposal`：准确商户/收款人/账户/产品、金额、费用、到期、幂等键、版本和风险结论。
- `TaskCheckpoint`：已成功动作、仍未知动作、资金预留、取消意图、最后可恢复位置。

状态：`collecting → investigating → planning → awaiting_confirmation → executing → verifying → completed`，异常进入 `blocked / unknown / partially_completed / cancelled`。取消任务只能停止未来动作；已经成功的支付或挂失不能被前端取消直接抹除。

LLM 负责意图解析、选择工具、解读已验证结果和提出下一步。确定性代码负责适当性、额度、金额、份额、现金流、权限和执行。模型无权制造审批 token 或更改工具返回状态。

## C4 开发包

| 编号 | 范围 | 交付 |
| --- | --- | --- |
| C4.1 | 稳定基线与共享账本 | 修复当前发布失败；账户、预留、待结算、目标分配统一读模型 |
| C4.2 | 六领域 Service / Provider | 联系人和 AA、通用报告/订阅、理财申赎、卡片五类动作、服务订单 |
| C4.3 | 领域工具与 Schema | 每领域 read/prepare/query；高风险 execute 仅服务端授权路径；输入白名单和数据权限 |
| C4.4 | 计划与分步骤确认 | 任务依赖、独立确认、修改后失效、部分拒绝、授权范围可编辑 |
| C4.5 | 持久运行和恢复 | 超时/预算上限/停止、新消息导致旧计划失效、进程重启、部分成功与补偿 |
| C4.6 | 工作台生成式 UI | 复用组件注册与渲染；新增收款人、产品对比、持仓/结算、卡控制、任务步骤和 Inbox 卡片 |
| C4.7 | Agent 评测与提交 | 六领域真实多轮、工具轨迹/来源覆盖/无越权、离线回退、三宽度体验 |

技能建议保留既有十项并按需扩展理财操作、卡片管理、联系人/AA；先冻结每个技能的输入、允许工具、准备动作、确认、失败和评测。不能把“注册了技能”当成领域能力已完成。

## C5 模拟环境和评测

四个稳定模板各配三种难度：正常、需补充/拒绝、执行异常。共享原旅行基准及新增完整年度/产品/卡片/订单数据。模型看到安全摘要和工件引用，不能看到密钥或未经必要过滤的完整文件。

第一批至少 36 组脚本化多轮案例，覆盖六领域各六组：成功、歧义、拒绝、状态过期、注入、执行未知。另有跨领域部分成功、重新确认和进程恢复案例。

真实模型先跑每领域两组主任务和两条组合任务，限制调用数和预算。报告意图/工具选择正确率、证据来源覆盖、未经授权写入数、重复扣款数、任务完成率、恢复成功率；模型失败必须计入失败或明确降级，不能仅以离线回退通过证明模型通过。

## C7 验收与取舍

除了六类共同验收，必须证明用户修改收款人、金额、商户、风险偏好或期限后，旧预览不能执行；新消息不能导致重复任务；跨会话不能读写他人计划；提示注入不会转成工具命令。

优势是自然语言覆盖广、Agent 轨迹可证明、能接住临场追问。代价是产品需要更强的状态解释，否则用户只看到长时间“正在思考”。所有步骤都应有必要的结果/下一步，技术轨迹折叠在详情里。

反馈可直接指定 C4.x：更重视自主规划还是稳定表单、能接受多少等待、是否保留四模板限制、真实模型评测预算及团队可投入人数。
