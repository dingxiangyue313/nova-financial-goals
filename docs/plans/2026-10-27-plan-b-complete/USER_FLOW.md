# 方案 B：完整用户流程与页面规格

依赖：[产品总纲](README.md)、[技术方案](ENGINEERING.md)、[数据与验收](DATA_AND_ACCEPTANCE.md)。所有金额、日期与结果来自服务端工件。

## 2. 全局交互规则

1. 一个任务阶段最多一个主要 CTA；次要操作保留/稍后/查看依据清楚可见。
2. 有多个任务时首页显示最相关目标和待办数量，不同时弹出多个强制确认。
3. 显示财务演示日和数据截至时间；模型/系统真实调用时间不替代财务日期。
4. 事实、假设、预测、限制使用文字标记，不能只靠颜色。
5. 所有金额先在服务端整数分计算；前端只格式化，不独立推导“还差多少钱”。
6. 关闭预览不执行；关闭执行界面不取消已经提交的业务。
7. 对话和表单指向同一个工件；从其中一个改金额，另一个旧确认必须失效。
8. Modal 一次一个；证据转向确认先关闭旧抽屉；焦点进入并在关闭时返回触发项。
9. 刷新后恢复当前工件和状态；不重放写请求来“找回页面”。
10. 通用加载显示正在核对哪项事实；异步订单显示状态查询，不能一直转圈。

## 3. 首页 F01

优先级：目标状态 → 资金解释 → 当前需要行动 → 其他目标 → 安静摘要。

目标卡展示：已准备/总预算、其中现金/预留/已预订、计划日期、必要检查项、下一步；对旧钱包保留“账户已存”而新增“目标已准备”指标。

消费卡保持截图中的青绿色视觉：本月消费、异常增量、即将续费、工资前最低余额；点击进入有证据的账单。缺数据时隐藏不可复算指标并给出补充入口。

状态文案示例：

- 正常：“按当前工资和账单假设，预计 4 月 26 日准备好资金。”
- 缺余额：“账单已整理，仍需确认余额才能安排转入。”
- 待收：“同行待付 ¥99.50，暂未计入可用资金。”
- 待结算：“赎回预计下一模拟交易日到账，今天还不能用来付款。”
- 局部成功：“机票已确认，住宿未完成。先处理住宿，不会重复购买机票。”

“模拟数据”可查看数据说明，不能成为失败结果选择器。

## 5. 联系人、AA、定时转账细节

### T-F1 联系人转账

输入“给小林转 ¥300”→脱敏候选列表→选定联系人→显示姓名/账号尾号/最近核对日期→金额和备注→来源和手续费→转后余额与目标影响→确认→服务端回执。

修改联系人信息后需重新核对；“备注”和商户名称是数据，不是工具指令。遇到陌生收款人或不匹配手机号，要求用户选择或补充，不自动发送。

### T-F2 AA

总额 ¥398.01，四人均分；我的份额 ¥99.51、其他三人各 ¥99.50（按固定参与人顺序分配余分）。如果我已垫付全部款，确认页明确“仅创建收款请求，不再次支付晚餐”。

卡片显示已收 2/3、待收 ¥99.50，已收金额和余额关联到具体收款事件。关闭剩余请求会停止后续请求状态，不抹除已收账。

### T-F3 周期计划

固定日和工资事件分开选择。日期月末按明示规则处理；工资触发显示可识别的来源、金额范围、有效窗口与缺失策略。计划暂停/恢复/取消均需准确确认，取消后恢复需新授权。

## 6. 故事二：出发前资金和支付修复

| 步骤 | 触发 | 展示 | 可行动选项 |
| --- | --- | --- | --- |
| R01 | 新报价即将到期，活期不足 | 钱在持仓中；金额与预计赎回到账日 | 保留现金等待/赎回预览/换日期 |
| R02 | 赎回确认 | 份额、费用、净额、模拟 T+1、不可保证旧报价 | 确认赎回或取消预览 |
| R03 | 订单已提交未结算 | 钱仍不可花，旧报价到期 | 等待到账并提醒；不重复赎回 |
| R04 | 结算确认事件 | 可用资金更新，原报价标记过期 | 重新询价，旧支付确认失效 |
| R05 | 新报价、卡锁定 | 资金足够，支付方式受限 | 确认普通解锁/换卡/稍后 |
| R06 | 若卡挂失 | 不提供普通解锁，显示受影响付款 | 换卡或模拟补卡流程 |
| R07 | 机票成功、住宿失败 | 已支付、仍预留、已释放各项分别列示 | 只换住宿；不重付机票 |
| R08 | 部分退款处理中 | 已取消但资金未到账，当前缺口 | 查询退款/等待/重新规划，不当现金使用 |
| R09 | 结果仍不确定 | 最后查询、已尝试步骤、下次可查时间 | 查询原操作、暂停未来步骤、人工问题包 |

修复比较最多三项：“保持原行程换住宿”“推迟一天”“保留成功订单并暂缓剩余”，每项说明需要改变的条件、费用、日期和新确认。系统不自动降低保护额。

## 7. 故事三：长期目标与理财

目标创建→期限和保护资金→与旅行目标的资金冲突→明确优先级→问卷→规则筛选→比较三产品和保持现金→准确申购确认→待成交→持仓→目标跟踪→赎回→结算→凭证。

风险问题一次集中在一张可编辑卡里，不用多轮机械追问已知字段。用户明确表示不能承担本金波动时，过滤不匹配产品并解释；若无合适产品，保留现金也能完成任务。

比较维度：风险、最短持有、最早可用日、费用、模拟收益假设、压力情景和来源。选择后显示“哪个目标为这笔钱让出了额度”；如果用户不愿调整，则减少申购或不执行。

申购确认页不显示已获得份额；赎回确认页不显示余额已增加。成交和结算事件分别推动状态。

## 8. 卡片完整入口

| 动作 | 需要展示 | 确认后结果 | 恢复 |
| --- | --- | --- | --- |
| 申请 | 虚构产品、功能、费用、已有合成资料 | 审核中/通过/拒绝；通过后按规则激活 | 查询原申请、补充合成字段、换卡产品 |
| 调额 | 当前/申请/批准额度、原因、时间 | 已调额/部分批准/拒绝 | 说明不增加现金，可申请较低额度 |
| 交易限制 | 当前开关、范围、金额/时段、生效期 | 新规则版本 | 订单已开始仍以付款时新规则检查 |
| 临时锁/解锁 | 受影响支付、卡身份和当前状态 | 当前卡新状态 | 新版本覆盖旧预览；不可解锁挂失卡 |
| 挂失 | 新付款被阻断、订阅受影响、不能普通恢复 | 挂失和凭证 | 换支付方式、模拟补卡、商户交接 |

所有卡只显示尾号和虚构身份；默认不把技术 Token、签名或权限引擎名称放到用户主流程。

## 9. 统一确认 F06

固定顺序：动作 → 对象 → 金额/份额 → 费用 → 何时生效/到账 → 资金与目标影响 → 失效/恢复条件 → 确认与暂不操作。

| 动作 | 必须冻结的字段 |
| --- | --- |
| 转账 | 来源、收款身份版本、去向、金额、币种、费用、时间 |
| AA | 原始垫付证据、参与人、整数分份额、截止时间、仅请求还是支付 |
| 订阅 | 商户、订阅版本、停扣日期、已付服务期限、退款/费用 |
| 申赎 | 产品/条款版本、金额或份额、费用规则、到账日规则、目标资金 |
| 卡片 | 卡 ID/版本、动作、范围、额度、生效期与不可恢复说明 |
| 订单 | 报价、商户、全部商品/税费、退改、支付方式、账户、授权和到期 |

数据变化时显示具体变化与新旧值，旧确认禁用，提供“重新核对”。取消对话框可随时做；执行提交后按钮切成查询结果。

## 10. 统一状态和出口

| 状态 | 页面应做什么 | 不能做什么 |
| --- | --- | --- |
| 加载 | 告知读取/核对哪部分 | 虚构进度百分比 |
| 空数据 | 指向合成样例/补充字段 | 用默认数值假装结论 |
| 部分覆盖 | 披露缺口，允许历史分析 | 生成确定性可执行预算 |
| 预览过期 | 展示变化，重新准备 | 继续执行旧 Action |
| 执行中 | 禁止重复确认，可查状态 | 关闭页面自动取消资金操作 |
| 未知 | 保留未确认资金占用，查询原操作 | 把未知当失败释放资金或再扣一次 |
| 局部成功 | 分开显示成功/失败/待核对 | 全部变绿或整体前端回滚 |
| 人工处理 | 生成可复制脱敏问题包及已尝试步骤 | 未经用户指令向外发送 |
| 离线 | 只读摘要、最后时间、暂停写入 | 排队自动提交资金操作 |

## 11. 通知与可访问性

重要变化才通知：工资缺失导致目标延迟、订阅涨价、卡片阻断必要支付、订单未知/部分成功、赎回到账或退款到账。普通交易记录静默保存在动态。

每个通知可查看依据、稍后、关闭同类提醒或进入具体任务；不重复创建相同主题。恢复后旧通知标已解决。

360/768/1440 均保持完整信息，横向表格可转比较卡；表单有 label、错误与焦点关联；弹层焦点闭环；支持 reduced-motion；图表有文本摘要；状态有文字和图标；危险动作有明确名称。

界面审查顺序：F01/F02 → 数据与证据 → 理财 → 卡片 → Inbox/订单 → 修复/凭证。先审信息和状态，再调间距和动效。
