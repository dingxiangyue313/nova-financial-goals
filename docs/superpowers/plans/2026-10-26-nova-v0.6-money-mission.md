# NOVA v0.6 Money Mission Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship one production-shaped simulated Japan Trip Money Mission that carries a user from evidence-backed bill analysis through verified subscription cancellation to an event-triggered savings transfer, with durable recovery and evaluation.

**Architecture:** Extend the existing `DemoState`/SQLite artifact model with additive, Zod-validated Money Mission contracts. Keep parsing, reconciliation, bill analysis, forecasting, merchant behavior and transfer scheduling in small deterministic server modules; expose them through version-bound actions and the existing Permission → Risk → Execute → Verify → Audit chain. Add one focused Money Mission UI flow inside the current NOVA shell, while retaining the existing goal workspace and treating external-agent Skills 6–7 as disabled P1 registrations.

**Tech Stack:** TypeScript 7, Node.js 22, React 19, Express 4, SQLite (`node:sqlite`), Zod 4, Tailwind CSS 4, Node test runner, Playwright, Promptfoo; server-only statement parsing with `multer`, `csv-parse`, `exceljs`, `pdfjs-dist`, and `tesseract.js`.

**Spec:** `docs/superpowers/specs/2026-10-26-nova-v0.6-deepening-design.md`; companion behavior contracts: `USER_FLOW.md` and `AGENT_SPEC.md`.

## Global Constraints

- Baseline is commit `432d85eeb38e0c7d301429a1f72e79f0df7a2290`; preserve existing APIs and historical SQLite sessions through additive defaults and migrations.
- Preserve NOVA's current navigation, teal palette, mobile frame and goal-first home priority; route major visual changes through owner review before merge.
- Store money as integer cents, dates as ISO `YYYY-MM-DD`, timestamps with offsets, and evaluate user-facing dates in `Asia/Shanghai`.
- The authoritative current balance comes only from a simulated connection snapshot or an explicitly confirmed balance snapshot; statement history never overwrites it.
- The authoritative saved amount comes from the goal wallet or a user-confirmed goal draft; it is never inferred from transaction history.
- Competition builds default `NOVA_ALLOW_STATEMENT_UPLOAD=false`; bundled synthetic samples remain fully usable, and raw file contents never enter prompts, model logs or product analytics.
- Deterministic services own parsing, classification evidence, calculations, state, permissions, risk, execution and verification. The model may route, clarify and explain only allow-listed values.
- Every financial write passes Permission → Risk → Execute → Verify → Audit and is idempotent; `unknown` and `failed` never appear as success.
- A confirmed recurring-transfer plan authorizes matching scheduled executions, but every occurrence still re-runs Risk, idempotency and Verify and receives its own Receipt.
- P0 frequencies are one-time and monthly only. Every goal can have at most one active monthly plan.
- A salary-relative plan triggers from a verified salary event; absent a match by day 27 at 23:59, that period is skipped without fixed-date execution or automatic catch-up.
- Subscription savings enter forecasts only after merchant verification returns `nextChargeSuppressed=true`.
- Skills 1–5 and 8–10 are P0. Skills 6–7 remain registered but disabled P1 Stretch capabilities and do not block core release.
- Background behavior exists only while the server process runs; UI copy must not imply browser-only background execution.
- The complete core flow must pass at 360, 768 and 1440 px, keyboard navigation, reduced motion and WCAG AA contrast.

## Review Focus

- A CSV/XLSX/PDF/image import containing plausible balances must still leave `Account.balanceCents`, `Finance.checkingCents` and `Goal.savedCents` unchanged; Task 3 owns this regression test.
- A cancellation that times out or later verifies as failed must retain the next CloudBox charge and keep forecast savings at zero; Task 5 owns this test.
- A late or missing salary must not cause a 26th-day debit or a later catch-up; Task 9 owns this test.
- A Twin change between preview and confirmation, or reuse of an idempotency key with changed input, must fail without partial state; Tasks 3, 5 and 8 own these tests.
- Prompt injection in statement descriptions, cross-session artifact IDs and raw-file/log leakage must be rejected or isolated; Tasks 2, 3 and 15 own these tests.
