# 安全自评报告（演示版，2026-10-12）

## 范围

系统只处理模拟目标、模拟现金流、模拟授权和模拟资金动作。没有真实银行连接、支付通道、账户登录或实名信息。演示者输入的自由文本可能由 DeepSeek 处理；启用模型前应避免输入真实个人财务资料。

## 现有控制

| 风险 | 控制 | 残余限制 |
| --- | --- | --- |
| API Key 泄露 | `DEEPSEEK_API_KEY` 只由服务端读取，`.env` 不进 Git，模型请求不回传 Key | 服务器管理员需妥善管理环境变量与备份 |
| 越权访问 | 签名 HttpOnly 会话 Cookie；MCP 独立 Bearer 令牌绑定会话 | 无用户注册；令牌持有人可访问对应模拟会话 |
| 擅自执行 | 仅模拟资金；明示授权类别、单笔/总额度、到期日；异类请求需逐次确认 | 演示默认没有真实银行风控能力 |
| 过度提醒 | 无目标投入缺口或低于显著阈值不推紧急影响 | 阈值需在真实数据上校准 |
| 重复扣款 | 每个外部请求有幂等键；重复参数返回原凭证，冲突参数拒绝 | SQLite 单实例部署；跨实例需共享数据库与协调机制 |
| 批准被篡改或重复使用 | Approval Snapshot 绑定 action、参数、Twin Version、期限与 SHA-256；Token 短期且一次性 | 当前为模拟审批，不连接真实身份系统 |
| 外部请求伪造或重放 | HMAC 覆盖 Agent、会话主体、时间戳、Nonce 和正文；5 分钟窗口，Nonce 持久化去重 | 共享密钥仍需由部署方轮换和安全分发 |
| 状态不明 | 超时为 Unknown，不改余额，要求查询原操作 | 无真实银行对账能力 |
| 模型幻觉与 Prompt Injection | 财务决策和执行由确定性规则计算；输入先做注入检测；UI 卡片只重排白名单，双端 Zod 校验，非法类型降级为不可操作说明卡 | 自然语言解析仍需用户核对 |
| CSRF/跨域 | SameSite=Lax Cookie、同源 Origin 检查、生产 Secure | 部署前应配 HTTPS 与入口访问控制 |
| 审计缺失 | Request、Decision、Approval、Operation、Receipt、Twin Version 形成 SHA-256 Hash 链，可导出 JSON/CSV 并验证 | 拥有数据库文件的管理员仍可整体重写数据；非合规级 WORM 存储 |
| 滥用与敏感日志 | 请求大小限制、本地 IP 限流、结构化元数据日志；不记录正文、Key、签名或完整账户标识 | 多实例限流和正式告警留到部署阶段 |

## 上线前检查与未完成项

- 阿里云域名、HTTPS、端口与反向代理仍需在真实实例上核对。
- 面向公网的演示仍需增加基础访问控制、跨实例限流、监控告警、密钥轮换与备份策略。
- 不将此原型用于真实支付、真实资产建议、个人敏感数据或生产银行系统。
- 深度安全审计与渗透测试未实施。此报告是团队自评，不构成安全认证。
