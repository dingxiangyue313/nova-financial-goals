# NOVA Agent 阶段 7 验收报告

日期：2026-10-21。范围：当前 `codex/agent-task-state` 工作区，全部账户、流水、资金和时钟均为隔离模拟数据。此报告区分可重复的离线证据与真实模型质量。

## 三层验证

| 层 | 入口 | 判断方式 | 本次结果 |
| --- | --- | --- | --- |
| 计算、状态与安全 | `npm test`、`npm run test:properties` | 整数分、日期、来源、硬约束、确认、幂等、审计、跨会话、并发及重启的确定性断言 | 119/119 测试通过；属性测试 5/5 通过 |
| 脚本化模型编排与整体验收 | `server/agent-runner.test.ts`、`server/agent-acceptance.test.ts`、`server/monitor-worker.test.ts` | 注入脚本决策，检查工具反馈改变下一步；从调查、修改、确认到监测修复再确认 | 已通过，属于协议与状态验证，不代表 DeepSeek 自主质量 |
| 真实模型多轮任务 | `npm run eval:agent:real` | 单独启用，最多 24 次模型决策；隔离 SQLite 与模拟数据；记录每场景指标，硬安全条件由代码断言 | `skipped`：未明确启用，无真实模型质量结论 |

真实模型运行方式：先在服务端环境设置 `DEEPSEEK_API_KEY`，再设置 `NOVA_RUN_REAL_MODEL_EVAL=1`，运行 `npm run eval:agent:real`。`NOVA_EVAL_MAX_CALLS` 可设为 1–24 的整数，默认 24。入口不属于 CI，默认不会联网；它不打印 Key、原始消息或模型回复，只输出聚合结果。每个场景的模型决策上限仍受 Agent 本身 6 步、12 次只读工具、45 秒运行预算约束。评测将真实模型输出交给同一白名单、候选来源与硬约束校验；质量未达标会如实记录，违反只读或证据边界则失败退出。

四个真实模型样本分别为：原条件可行、提高月投入后可行、给定有限条件下未找到解、历史数据不足。每个样本提供连续两条用户消息，并独立建会话和数据库。输出字段包括任务完成、约束失败次数、候选数字证据覆盖、无效追问、重复候选、模型/工具调用数、耗时与回退。通知准确性由确定性的风险与 worker 测试评估；当前 worker 不调用模型，因此不能将该指标算作真实模型成绩。

## 离线验收范围

- 模糊目标、逐步补全、只改金额、日期范围不漂移、拒绝建议、未知奖金和取消：`workspace.test.ts`。
- 原方案可行、候选失败后改变条件再试算、有限候选无解、数据不足、模型异常与非法工具：`agent-read-tools.test.ts`、`agent-runner.test.ts`、`agent-acceptance.test.ts`。
- 执行确认、旧任务与 Twin 版本失效、跨会话隔离、重复确认、超时和幂等：`candidate-application.test.ts`、`banking.test.ts` 及 HTTP 测试。
- 显著变化后重规划、低价值变化安静、暂停、静默时段、重复通知与跨进程租约恢复：`monitor-worker.test.ts`、`risk.test.ts`。
- 单条闭环：`agent-acceptance.test.ts` 在同一模拟会话执行“调查失败 → 用户改月上限 → 再试算 → 明确确认 → 启用监测 → 显著变化 → 只读修复候选 → 再确认”，并检查确认前目标未改变、保护资金未动。

以上测试提供失败即阻断的确定性安全断言。未发现绕过确认、无来源候选被应用、重复执行、跨会话读取、旧任务写回或伪装后台运行的交付阻断问题。数字证据覆盖等真实模型质量指标须在实际 opt-in 运行后才有成绩；没有同场景旧版本可运行基线，因此不报告提升百分比。

界面验证：`npm run test:e2e` 在 360、768、1440 像素三种宽度运行 72/72 通过，包含无障碍、PWA 离线、候选确认与监测。最初全量运行发现两个测试时序问题：工作台测试要求瞬时欢迎页必定可见，PWA 测试无限等待 service worker；改为等待稳定工作台与有界检查注册状态后，受影响单项及完整 72 条均通过。`npm run lint`、`npm run build` 和 `git diff --check` 通过。

`npm run eval:promptfoo` 本机未完成：仓库未安装 `promptfoo@0.124.1`，Windows 启动方式已修正，但通过 npm 临时取得并启动该版本的过程超过 120 秒上限。npm 仓库连通检查成功；原因尚未定位，不能把 Promptfoo 记为通过。配置仍是无 Key 的确定性意图与回退评测，不属于真实模型评测。CI 保留原评测命令，需在可取得该版本工具包的环境重跑。

## 演示入口与限制

无 Key 演示：`npm run dev`，打开工作台，以“年底去日本旅行，预算八千，已存零元，每月最多两千元，应急金不能动”开始；核对只读候选并单独确认激活，再点击启用目标监测。推进模拟流水以观察显著风险，进入风险会话核对来源和修复候选，再单独确认。界面会把无 Key 路径标为规则试算/确定性回退。可重复的程序化完整演示入口为 `npx tsx --test server/agent-acceptance.test.ts`。

本项目的预测是基于月度现金流和有限模拟历史的情景试算，不是概率保证；当前只监测活跃主目标，仅在应用内通知。浏览器关闭后依赖服务进程存活。真实模型样本只有四类，不能推断生产环境总体质量。
