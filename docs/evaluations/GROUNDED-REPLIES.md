# 第三步：统一回复依据

2026-11-02。

## 实现

- `server/conversation-replies.ts`：目标回复依据已保存的统一任务状态生成。明确区分新建、切回、字段修改与清空；列出实际预算、日期与已存金额，只追问当前缺失的信息。未提及字段保持原值。正常导航只说明前往功能与待核对事项，不声称已付款。
- `server/conversation-facts.ts`：账户余额只引用当天、币种和金额匹配的快照；缺失、过期或不一致时不报数。目标资金读取实际资金账本，不将聊天草稿中的已存金额当成已分配资金。多个目标不明确时列出选择，不擅自挑主目标。订单查询只引用已有订单；进度预测必须有启用的计划、当前余额与流水依据，调用现有计算引擎后才能回答。
- `shared/product-knowledge.ts`：一般产品说明与用户账户事实分离。语义模型选择说明引用，程序生成回复，不转发模型的自由账户结论。未收录的说明明确提示依据不足，不编造。只读查询和说明可按各自来源组合，避免只回答复合请求的一半。
- `server/store.ts`：回复来源关联到实际助手消息并保存；事实回复包含快照、账本或计算记录的版本与日期。来源细节不作为技术术语展示给用户。
- `AgentComponentRenderer.tsx`：未确认的已存金额及保护资金显示“待确认”，避免将内部默认值显示成已知事实；原布局保留。
- 只读事实对象ID与聊天任务ID分离；只读查询不会恢复或修改聊天任务。仅年份、月份的时间精度保留，不能因为缺少日而丢弃同轮预算。

回复不接受模型自由生成的 `answer` 或 `question` 作为账户事实或追问内容。金融写入继续通过原确认、风险、执行和审计流程。

## 验收方法

按完整会话计成功：关键一步回复、字段或依据错误，整段失败。检查中文回复中的实际金额、日期、撤回、恢复、缺失数据提示与持久化的来源，不能用页面分类代替问答结果。账户及正式目标在测试前后必须一致。

真实API测试使用隔离数据库和明确的测试快照/账本；有当前数据、过期数据、无数据、多个目标及未启用计划等不同环境。对快照/计算结果的数值预期由测试文件预先定义，不让模型自评。

## 范围与限制

现阶段直接事实查询支持账户余额、已保存目标资金、已启用计划进度与旅行订单。目标账本的未预留金额不等于所有执行条件都已通过，仍需来源账户、账单和保护资金核对。未启用计划、无当前数据或未知商户结果不承诺完成、到账或成功。

一般说明仅限已审核的产品知识目录，超出目录会明确依据不足，不是无限范围金融问答。复杂影响试算、投资建议和所有商户状态未在本轮完整覆盖。语义选择仍可能波动，回归样本通过率不能作为线上准确率保证。

复现：`npx tsx scripts/evaluate-grounded-conversations.ts <用例JSON> <结果JSON>`，设置独立 `NOVA_DB_PATH`。真实浏览器：`node scripts/smoke-grounded-replies.mjs <结果JSON>`。
