# 第一、二步：任务状态与业务能力目录

2026-11-02，本次范围只包含任务状态机制与业务动作驱动页面，不包含第三步的全面回复重构或模型一致性纠正器。

## 实现

- `shared/conversation.ts`：每个任务独立记录名称、目标/服务类型、已收集字段、进度、最近操作、更新时间、字段来源及版本。未提及字段保持，显式清空才清空；新任务从空字段开始。
- `server/conversation.ts`：先独立确定任务选择，再决定字段处理与追问。模型即使选择clarify，只要明确指向已有任务，程序也先切换该任务；缺少日期不再阻止恢复已知预算。多个候选不改当前任务，返回真实候选供选择。取消任务不能自动恢复。
- `server/chat-controller.ts`：根据已切换的任务投影生成原有目标卡或页面导航，不把模型的追问分支当作“尚未切换”。
- `shared/capabilities.ts`：21项业务能力统一目录，包括目的、区别、页面收集字段和确定的页面映射。模型只接收业务定义，不接收页面地址；前端页面导航也从同一目录生成。
- 服务动作切换时创建独立草稿，旧任务保持以供返回；金额/日期及字段依据继续通过确定代码验证，没有按单句需求写成功分支。
- 完整日期元数据与目标日期统一规范化，避免模型给出完整日期后程序继续将其当作缺日状态；仍需当前消息中的日期证据，不能凭空指定月初。

## 验证

原有完整会话回归：20/20。

新冻结验收集：`steps12-acceptance-cases.json`，20段46轮；分别运行A、B、C，原始结果全部保留。A和B均20/20。真实浏览器发现日期元数据状态问题后修复，C为19/20（95%）。A/B在该修复前，因此不是最终代码三次相同条件的稳定性证明。重复同一批20段也不等于60段独立样本。

C唯一失败：“再看看目标目前实际可支付多少”，模型选择解释该功能并询问是否打开，没有直接选择业务动作；记为会话失败。所有会话账户及正式目标数据未改变。此结果不代表所有自然语言或完整金融任务均有95%成功率。

本地44项联合回归通过，增加日期元数据验证后核心8项通过；TypeScript与构建通过。包含字段隔离、跨任务恢复、候选歧义不自动切换、取消不可恢复、业务动作与页面唯一映射、金额证据和日期年份继承。

## 仍存在的限制

程序现在能可靠落实明确的任务选择，但模型仍可能选择解释而非业务动作，或无法正确判断用户指向；本次未开发第三步的一致性纠正器。未来需用新的独立对话验收这些概率性问题，不按既有验收句子追加例外规则。金融执行仍必须经过原有确认、风险、验证及审计。
