# 统一聊天链路重构记录

日期：2026-11-02。代码已接入本地 `/api/agent/chat`，独立真实验收未达成，不能宣称完成质量验收或达到95%。

## 实现

`shared/conversation.ts` 定义模型业务命令和任务状态契约。`server/conversation.ts` 一次语义调用产生业务操作、任务选择及字段证据；确定代码验证金额和日期、转换整数分、继承日期上下文，并更新任务状态。业务能力是单一操作标识，避免同时选择操作类型和页面导致不一致。

`server/chat-controller.ts` 读取统一状态，语义理解，更新状态，生成原前端兼容的回复或导航。目标流程直接传入已验证的状态投影，不再二次调用 `understandGoalMessage`；不经过旧关键词意图识别。旧解析器仅为旧接口保留。

`server/store.ts` 增加会话状态存储和版本冲突校验。各任务独立保存字段，新任务不继承旧目标字段；暂停切换后可恢复指定任务。已有目标和导航草稿读入新状态。目标任务与卡片沿用既有计算、确认和审计模块，是统一状态的投影。

`AgentWorkspaceScreen` 将正常追问展示为聊天消息，错误时保留输入。取消草稿不执行资金操作。金融写入仍使用原确认、权限、风险及审计机制。

模型不再承担金额计算。保留数值、日期规范化和合法性验证；没有按用户单句设置本地成功响应。原页面布局未重做。

## 验证与失败

- 本地联合回归40/40，追加的金额证据和日期年份测试也通过；最后核心测试8/8，TypeScript与构建通过。
- 浏览器3/3：中文输入、功能导航、正常追问与服务失败展示。此组使用mock检查前端展示，不证明模型理解准确。
- 真实开发对话集20段，逐轮检查字段和任务，经历15/20、9/20、18/20、17/20后达到20/20。全部原始结果保存为 `unified-first.json` 至 `unified-fifth.json`。这些用例参与开发，不能称为独立验收。
- 新冻结验收集为 `unified-holdout-cases.json`，结果 `unified-holdout-result.json`：3/20会话通过。随后连续上游HTTP失败，独立诊断确认DeepSeek返回402。不能排除剩余未完成会话仍有语义错误，也不能将它们从产品可靠性分母去掉后声称通过。
- 无密钥写入代码、日志或报告。不能自动充值、更换密钥或改用未经授权的模型。
- 浏览器真实API冒烟脚本已准备，但本地页面加载超时，未取得真实浏览器端到端通过结果。

## 未完成验收

需要服务账户计费恢复后重新运行未参与调优的完整会话集。如果验收集被用于修复，就必须另留新验收集。确认从页面发起的真实流程，再检查目标约束、计算方案、确认及任务生命周期。不把mock前端测试或模型字段分类代替用户任务成功率。

现有新链路优先覆盖目标字段、功能导航、任务切换、取消与一般解释。额外支出影响计算、推荐方案选择、用户确认等更复杂动作仍需独立业务命令与完整验收；不应让自由解释冒充账户事实或已经计算出的结论。复杂未来收入等约束也未在当前目标字段协议中完整表示。
