# NOVA 聊天跨场景评测（2026-11-02）

> 更正：本报告中的 97/100 不是产品问答准确率，也不能证明真实用户任务成功率达到 95%。80 条主要是页面分类；20 条沿用既有固定对话，测试用例又用于修改提示词，存在测试污染。各轮代码与两条输入发生变化，表格不能作为相同条件的前后提升证据。数据仅用于诊断和回归，不作为交付质量门槛。此前将其对用户表述为达到准确率要求是不恰当的。

真实调用本地 HTTP 接口与 DeepSeek，无模型响应 mock。

## 覆盖

- 20 条目标表达：中英文金额单位、预算、日期、已存、月存上限及修改。
- 42 条功能导航：21 个目的地，各两种说法，包含转账、AA、理财、卡片、账单、订阅、旅行、资金分配、转入安排、试算和计划调整。
- 8 条知识解释意图、6 条模糊或多个任务请求、4 条否定请求。
- 20 轮完整聊天：修改金额和账户、取消与禁止恢复、返回页面、切换任务、清除旧草稿、多轮目标信息累积。

80 条主要检验意图、页面目的地和是否应追问，不代表对回答中每项金融事实的独立核验；20 轮检查完整聊天状态及部分目标字段。本轮不验证真实银行付款，也不代表所有页面的端到端交互覆盖。

## 修复

1. 区分目标资金归属、未来投入方案、转入执行时间安排。
2. 目标可支付金额进入资金分配；余额变化问题进入收支试算。
3. 已提供具体新金额/日期时继续目标解析；仅请求修改计划时直接打开计划页面。
4. 模型单次等待由 12 秒调整为 25 秒，保留最多一次重试，未采用关键词成功响应掩盖失败。
5. 数据库锁等待在首个建表前设置，修复热重启时因数据库锁冲突退出的问题。

## 评测过程与局限

- 保留连接失败、限流、首轮、各轮复测原始文件。限流和未启动阶段单独保留，不算语义准确率。
- 原始首轮的两条省略修改指令没有上下文，后来补充目标名称；修改前后的记录均保留，不能把所有轮次当作完全相同输入的统计比较。
- 最后完整覆盖的三条失败是新预算、新日期和每月转入分类；补充规则后这三条及九条关联用例全部通过。
- 额外本地回归测试 11/11 通过，TypeScript 检查通过。模型结果可能波动，97% 是本组用例的通过率，不是线上保证。

复现脚本：`scripts/evaluate-chat-scenarios.mjs`、`scripts/evaluate-chat-memory.mjs`、`scripts/evaluate-chat-badcases.mjs`。各脚本最后一个参数指定输出 JSON 文件。
