# NOVA 竞品分析：从 AI Banking 能力比较到目标驱动的产品定位

> 分析依据：用户提供的三张竞品矩阵截图与 Competitive Gap Matrix 对话摘录，并结合本项目 `PRODUCT.md` 的最终产品定位。本文呈现的是项目研究阶段的分析和产品决策依据；矩阵中的能力标记、星级和路线图判断未经逐项独立核验，不作为竞品当前公开功能的事实清单。

## 一、分析目的与范围

NOVA 面临的核心问题并非“还能给银行 App 加哪些 AI 功能”，而是如何让用户在不持续记账的前提下，知道一个具体生活目标能否按期实现，以及出现变化时该怎么调整。竞品分析因此要回答三个问题：

1. 自然语言、交易分析和工具执行等能力中，哪些已经是同类产品的基础配置？
2. 哪些能力可以借鉴，但不应直接成为 NOVA 的产品定位？
3. 在比赛演示和有限开发周期内，哪条用户体验最能把产品价值讲清楚？

对话材料选取 Revolut AIR、SBI NEOBANK ai、DBS digibot、Visa AI / VIC 与工行工小智作为比较对象。它们分别代表数字金融生活服务、生成式交互、银行与人工服务衔接、受授权的代理交易基础设施，以及传统银行的业务覆盖。这个样本用于启发产品取舍，并不代表对整个市场的完整覆盖。

## 二、比较框架

研究材料从用户可感知的体验和底层执行能力两个层面比较竞品。

| 维度 | 关键问题 | 对 NOVA 的意义 |
| --- | --- | --- |
| 交互入口 | 能否用自然语言提出、补充和修改任务？界面能否随任务变化？ | 决定用户是否需要在多个功能入口中寻找操作路径。 |
| 财务理解 | 能否结合交易、现金流、订阅和目标理解用户处境？ | 决定产品是回答账单问题，还是回答“我的目标能否实现”。 |
| 主动服务 | 能否发现值得处理的变化，并提出下一步？ | 决定 AI 是否只在用户提问后工作。 |
| 行动闭环 | 能否从洞察走到方案、授权、执行和结果反馈？ | 决定建议是否真正可操作。 |
| 权限与信任 | 是否限定金额、类别、商户和时效，并保留确认与审计？ | 决定代理操作是否可控、可解释。 |
| 开放能力 | 能否通过工具或 API 服务其他 Agent？ | 属于平台延展方向，但不是普通用户进入产品的首要理由。 |

原研究还使用 **Must-have、Borrow、Differentiate、Don't build** 四类标签：基础能力必须具备；成熟做法可以借鉴；差异点需要重点验证；高成本、弱主线的功能暂缓。这种分类比按功能数量比较更有助于确定 MVP。

## 三、竞品侧重点与启发

| 对象 | 研究材料中呈现的侧重点 | 对 NOVA 的启发 | 不能直接照搬的地方 |
| --- | --- | --- | --- |
| Revolut AIR | 财务分析、预算及生活服务连接较强。 | 借鉴把财务信息放进生活场景的思路。 | 仅增加消费分类、订阅或旅行服务，仍难回答目标能否按时完成。 |
| SBI NEOBANK ai | 自然语言任务与生成式 UI 是主要亮点。 | 用对话承接复杂任务，并让目标、方案和确认信息以合适组件呈现。 | 动态界面本身是交互手段，不能替代财务判断与行动建议。 |
| DBS digibot | 银行业务与人工服务衔接受到重视。 | 高风险或不确定场景应保留清晰的升级路径和用户控制。 | 不应把“AI 能做所有金融决策”当作默认承诺。 |
| Visa AI / VIC | 权限、代理交易与跨场景执行能力是重点。 | 将授权定义为金额、类别、时间等可检查的边界，并记录操作全过程。 | 底层支付和代理基础设施不是消费者首页最容易理解的价值。 |
| 工行工小智 | 传统银行业务覆盖和自然语言服务入口较深。 | 基础银行能力与安全体系是产品可信度的前提。 | 业务覆盖广度不等于围绕单个生活目标的连续体验。 |

这份研究的关键发现是**能力分散**：不同产品分别强调金融生活服务、生成式交互、人工交接、受控执行或银行业务深度。对 NOVA 而言，机会不是声称这些能力从未出现，而是围绕一个具体生活目标，把“理解现状—判断可行性—解释变化—提供调整—经授权行动”组成连续体验。截图中“四个方向同时具备”的结论应视为对所选样本的研究判断，不应扩展为全市场唯一性声明。

## 四、从竞品矩阵到 NOVA 的产品选择

### 1. 将目标可行性放在首页，而非功能清单

自然语言问答、流水分析和基础工具调用在矩阵中被归入 Must-have。它们能支撑体验，却不足以回答用户最重要的问题。NOVA 因此以旅行、学费、应急金、开店等生活目标为入口，优先展示“按当前资金情况能否按期实现”“主要依据是什么”“下一步可以调整什么”。内部 Financial Twin 用于组织账户、现金流和目标状态，但不作为面向用户的导航概念。

### 2. 将主动洞察收窄为“目标影响”

原对话提出 Proactive Financial Twin 和 Morning Financial Brief，强调 AI 不应只等用户提问。后续产品基线进一步收敛：NOVA 不做每日提醒中心，而是先判断变化是否真正影响已激活目标。普通波动进入安静摘要；显著变化才产生即时提醒，并说明证据、预计影响、不确定性和可调整方案。这一取舍把“主动”从提醒频率转为提醒价值。

### 3. 借鉴生成式 UI，但让信息服务于决策

SBI 方向启发了对话中的任务卡片和动态呈现。NOVA 的界面不是把所有财务数据堆进固定 Dashboard，而是按当前任务展示目标状态、方案对比、影响说明或授权确认。组件与金额由服务端契约和规则约束，避免模型自由生成可执行操作。生成式 UI 的作用是降低理解和操作成本，而不是单独充当产品卖点。

### 4. 将代理执行放在明确授权之后

Visa 方向启发了“有限授权”而非每一步重复确认：授权可以包含金额、类别、有效期等边界。NOVA 的默认行为仍是建议；模拟资金操作只有在用户逐次确认，或符合既有授权及风险规则时才执行。执行后展示结果和审计记录。这样可以演示 Agent 的行动能力，同时保留用户对关键财务动作的控制。

### 5. 控制首期范围

研究材料明确排除了语音优先、数字人、复杂投资建议、自研欺诈模型、真实银行 API，以及为展示复杂度而拆分大量 Agent 等方向。NOVA 的比赛演示集中在三条体验：目标规划、目标感知风险、受控模拟操作。外部 Agent / MCP 属于能力证明与技术延展，顺序上排在普通用户可理解的目标主线之后。

## 五、NOVA 的差异化表述

> **NOVA 不是让用户管理更多财务功能，而是持续回答一个生活目标能否实现，并在重要变化发生时给出可理解、可调整、可控的下一步。**

这一定位对应四层体验：

1. **看得懂现状**：从授权范围内的模拟账户和流水形成目标相关的财务概况，同时说明数据是否充分。
2. **判断得了未来**：以目标金额、期限、每月投入和受保护资金为条件，比较有限个可行方案及其假设。
3. **只提醒重要变化**：用目标影响而不是单纯“支出上涨”决定是否打扰用户。
4. **行动始终可控**：用户可修改方案、确认模拟操作、查看授权范围和执行记录。

这也解释了产品叙事的调整：早期研究曾以 Morning Financial Brief 作为首个演示候选；最终 `PRODUCT.md` 将 Goal Readiness & Plan 设为第一条体验，再由目标影响监测与受控执行承接。调整后的顺序先让用户理解价值，再展示 Agent 能力。

## 六、结论与后续验证

这份竞品分析为 NOVA 提供了**定位、优先级和体验顺序**，并非竞品性能测评。它支持将首页与第一条完整流程聚焦在目标可行性，借鉴生成式 UI 和有限授权，保留主动提醒与安全执行，同时压缩与目标主线关系较弱的功能。

后续若用于对外发表或正式商业判断，需要逐项复核竞品当前公开能力、上线地区与时间、用户可用范围，并补充更大样本的用户研究。现阶段访谈规模较小，也尚不能据此宣称用户留存、付费意愿或 NOVA 相对竞品的效果优势。
