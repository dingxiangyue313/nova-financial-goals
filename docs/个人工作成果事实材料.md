# NOVA 项目个人工作成果事实材料

> 用途：供撰写产品经理简历、作品集和面试案例时取材。这是一份事实梳理，不是简历成稿。
>
> 归属说明：用户明确表示项目的设计与前端工作由本人完成。项目文档将产品定位、范围、优先级、用户流程、信息架构、文案、原型及前端界面列为 Design Owner 职责。后端架构与安全规则有团队协作和授权参考来源，以下不将其全部记为个人独立开发。

## 1. 项目概况

- **名称**：NOVA，目标驱动的主动式 AI 财务副驾驶。
- **形态**：移动端优先的响应式 Web / PWA；当前为使用模拟财务数据的比赛演示版，不接入真实银行或真实资金。
- **目标用户**：有明确中短期资金目标、使用多个金融或支付渠道、又不愿持续手工记账的年轻用户。
- **核心问题**：用户看到余额和流水后，仍难判断旅行、学费、开店等目标能否按时实现，以及遇到财务变化时该如何调整。
- **核心链路**：创建目标 → 读取授权范围内的模拟数据 → 判断可行性 → 比较方案 → 激活计划 → 监测目标影响 → 提议调整 → 经授权执行模拟操作 → 验证与记录。

## 2. 本人负责的工作

### 产品研究与定位

- 参与前期用户访谈与需求收敛。现有研究约覆盖两位受访者，所得结论用于确定 MVP 方向，**不能表述为具有代表性的市场验证**。
- 将“能否按时实现生活目标”确定为首页首先回答的问题，将目标规划置于账本、交易明细和自动执行之前。
- 制定“目标优先、主动但保持安静、先解释再建议最后执行、风险越高用户控制越强”等产品原则；明确默认是建议，资金模拟操作需要逐次确认或符合预先授权边界。
- 编写并维护产品定位、目标用户、核心旅程、页面优先级、功能需求、边界、状态和验收标准。项目文档记录了从以 Morning Brief 为首条主线，调整为以 Goal Readiness → Plan Activation → Goal Impact 为首条纵向体验的取舍。

### 竞品分析与产品取舍

- 整理 Revolut、SBI NEOBANK ai、DBS digibot、Visa AI/VIC、工行工小智等案例，建立涵盖自然语言交互、主动洞察、目标规划、生成式界面、工具执行、授权、审计和外部 Agent 接入的能力矩阵。
- 用 **Must-have / Borrow / Differentiate / Don't build** 四类标记能力，区分比赛所需基础能力、可借鉴的成熟做法、潜在差异点和短期不值得投入的方向。
- 从矩阵中提出主动财务洞察、生活目标编排、生成式 UI 与有边界的 Agent 授权等候选方向；后续产品基线进一步收敛为“目标能否实现”这一消费者价值，不把技术能力本身当作首页卖点。
- 在 MVP 范围上优先建设目标可行性、方案比较、目标影响提醒与受控模拟执行；将复杂投顾、真实银行连接、语音优先、数字人和为展示技术而拆分多 Agent 等方向排除在首期之外。
- **证据边界**：上述矩阵是项目研究与策略工具，能力标签、星级和“市场空白”判断不宜在简历中写成经独立验证的行业事实。

### 产品设计与前端落地

- 独立承担原版 NOVA 的页面视觉与前端工作，设计移动端优先的信息架构：Home、Goals、Agent、Activity、Profile；首页突出目标状态、可行性和当前下一步。
- 设计目标创建、可行性判断、What-if 试算、方案比较、目标影响详情、Agent 工作台、授权确认、执行凭证和活动记录等关键页面与状态。
- 设计不同屏幕下的交互：手机端采用单列对话与卡片；桌面端将对话区与受治理的任务画布并排展示。考虑加载、空状态、数据不足、失败、离线和恢复等场景。
- 使用 React、TypeScript、Vite 实现页面、导航、响应式样式和对话式工作台。界面通过服务端返回的白名单组件展示目标、方案、影响、确认与凭证；写操作在界面上先呈现确认信息。
- 为财务信息建立清晰的信息层级与解释文案：展示目标是否按计划推进、判断依据、假设与不确定性；普通波动进入安静摘要，显著影响目标时才主动提醒。

### 推进与验收

- 将产品主线拆成三条可演示体验：目标规划、目标感知风险、经授权的模拟 Agent 操作；定义每条体验的用户流程与应展示的状态。
- 与后端架构负责人通过共享契约、状态含义和验收标准衔接，验收技术状态是否能被普通用户理解，以及各关键步骤是否有相应界面反馈。
- 仓库包含覆盖关键流程的 Playwright 端到端测试及无障碍检查。项目文档记录过 360、768、1440 px 等屏幕宽度的验收；这些是**原型测试结果**，不是上线后的用户转化或业务增长数据。

## 3. 可用于面试展开的决策案例

1. **为什么由目标而非账单开始？** 访谈与需求梳理显示，用户希望减少手工维护财务信息的成本，更关心具体目标是否可实现。由此将首页和第一条完整流程改为目标可行性与计划激活。
2. **如何利用竞品研究？** 竞品矩阵显示，自然语言入口和基础银行能力不足以形成清晰差异；团队保留必要基础能力，把体验重点放在目标驱动的主动建议与可控行动，并限制首期范围。
3. **主动提醒如何避免打扰？** 普通消费波动进入周摘要；只有变化显著影响目标、可解释且可行动时才建立即时风险提醒，并提供影响依据和调整路径。
4. **如何处理 AI 金融产品的信任问题？** 区分读取、建议、确认和模拟执行；界面明确展示权限范围、风险判断、确认内容与执行记录，避免让模型输出直接成为资金操作指令。

## 4. 写简历时需要保持的边界

- 可以表述为：**本人负责产品定位与需求、竞品分析、用户流程、页面与交互设计、前端实现**。若某项原型或视觉工作并非本人完成，按实际情况删改。
- 后端架构、权限引擎、MCP、安全规则和完整测试体系属于团队项目成果；除非能说明个人具体贡献，不写成“独立开发”。
- 不把约两位受访者的方向性反馈写成大样本研究结论；不编造用户增长、留存、转化率或预测准确率。
- 不把模拟银行操作写成真实银行接入、真实支付或已上线金融服务。
- 不把竞品矩阵的主观评分写成客观市场份额或严格验证过的竞品能力结论。
