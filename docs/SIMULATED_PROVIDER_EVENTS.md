# 本地模拟服务回报契约

这是模拟协议，并非真实银行或商户Webhook。原操作必须已获得用户确认，服务回报只能查询/推进原操作，不能提供新金额、收款人或创建付款。

- 身份：provider固定nova-sim-provider，HMAC绑定会话及严格Schema；密钥仅服务端环境变量，回报签名不持久保存到公共状态。
- 字段：事件id、domain（investment/booking）、subjectId、正整数revision、允许的状态、reportedOn。
- 日期：不得晚于模拟今天或早于原操作凭证日期。
- 去重：同事件id/同内容返回原状态；同id不同内容拒绝。内容摘要只在服务端存储，查询视图不返回。
- 乱序：revision小于等于当前游标时记录stale，不改现金/份额。更高版本不能使最终成功、失败或退款相关状态回退。
- 资金：理财结算还须满足原结算日期；pending回报即使过了日期也不自行变成settled。拒绝退款、赎回释放、订单捕获均沿用原操作幂等逻辑。
- 持久化：事件日志、游标、原操作与结果共处SQLite会话原子事务；真正服务重启测试验证去重与会话隔离。
- 测试投递：/api/demo/provider-events/send由服务端签名并投递合成事件；/receive验证签名。两个入口受既有演示控制开关限制，消费者不出现结果选择器。
- 只读显示：/api/services/provider-events仅返回本会话脱敏处理记录，前端为“模拟服务结果核对记录”。

生产环境需配置稳定的服务端签名密钥；未配置时仅使用进程级随机密钥，重启前签名会被拒绝，但已持久化业务结果和去重记录仍保留。真实外部网络重试/Outbox/密钥轮换/长期任务迁移仍不在本协议完成范围。
