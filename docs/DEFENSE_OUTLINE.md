# NOVA 答辩材料提纲

## 一句话与问题（约 45 秒）

**不用记账，也知道目标能不能按时实现。** 用户不缺余额和账单页面，缺的是“目标能否达成、变化是否重要、该怎么调整”的连续判断。现阶段访谈样本很小，这一定位属于 MVP 假设。

## 产品演示（约 3 分钟）

1. 原版首页：看目标、日期、已存与建议节奏，解释应急金独立保护。
2. 创建目标：输入自然语言，经 DeepSeek 或确定性回退解析；用户核对金额与日期。查看可行性，明确选一个方案再激活。
3. 连接模拟银行卡、微信支付和支付宝；推进演示时钟，让普通趋势进入安静摘要，显著累计趋势才解释缺口、预计日期和 A/B 调整。
4. 从“我的”创建交通类授权。交通请求 Execute，购物请求 Ask 并需用户确认，超限请求 Block；展示操作凭证、审计与撤销。

## 技术证明（约 90 秒）

- 单仓库原版 React 界面 + 新建 Express/SQLite 后端，共享 Zod 契约。
- 确定性 Financial Twin 和风险规则，模型只负责语言理解与白名单卡片组合。
- MCP 入口和网页模拟请求共用 Permission → Risk → Execute → Verify → Audit；幂等键防止重复模拟扣款，超时先查原操作。
- 独立演示会话、固定模拟时钟、无 Key 完整回退，保证现场可重现。

## 安全与局限（约 45 秒）

只用模拟账户与模拟资金，不接真实支付。Key 只在服务端。当前财务预测基于有限模拟历史与固定假设，需真实用户研究、数据接入与安全审计后才可能进入实用场景。
